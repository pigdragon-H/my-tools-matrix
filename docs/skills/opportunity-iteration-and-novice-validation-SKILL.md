# SKILL：機會情報迭代處理與創業藍圖小白驗證（通用版）

版本 v1.1 · 2026-07-04 · 撰寫者：Claude（依 Victor 指示建立與修正）
適用執行者：Manus、Claude Code、SuperNinja、或任何具備研究/實測/寫作能力的協作 AI
性質：**可重複執行的通用操作技能**，不綁定任何特定主題。OpenMontage只是這次的示範案例，未來遇到任何具備創業潛在價值的新項目，都照這份SKILL的步驟走。

## 這份SKILL要解決的兩個問題（Victor原話定調）

**問題一**：任何一個主題隨時間持續有新進展，舊做法是「回頭改文章」，但這樣看不出FU一直在追蹤這個主題的過程。正確做法：**標題必須不同，信息可以用1、2、3...這種序號累積出現，表示信息內容主體的價值演進**——不編輯舊卡片，開新卡片，用`topicId`串成同一條演進線。

**問題二**：創業藍圖真正的讀者，是**技術小白、但願意也會跟Claude、Gemini這類LLM AI協作的人**。**這是當今所有有熱情投入AI協作、卻不具備寫程式能力者的實際做法**——不是完全零基礎、什麼都不會，是「不寫程式碼，靠自然語言指揮AI」這種新型能力結構。教程好不好用，要用這種真實的協作模式驗證過，不能靠AI自己覺得寫得清楚就算數，這件事直接決定點擊率。

## Part A：機會情報迭代處理 SOP（通用，不綁定主題）

### A1. 觸發條件

- 一個已經有`topicId`的既有主題，出現新的技術進展/版本更新/重大功能
- 同一主題被多個獨立來源再次提及，且內容跟上一張卡片的重點不同

**不觸發的情況**：單純數字波動（star數、trending排名這類易變指標）不構成獨立新卡片的理由，順帶寫進既有卡片的AI視角區塊即可。

### A2. 執行步驟

1. **查證新進展是否真實**——去源頭（官方repo/文件）查證，盡量交叉比對至少2個獨立來源
2. **判斷這是不是真的「新價值」**——問自己：這則新卡片如果不存在，讀者會少知道什麼？答不出來就不該開新卡片
3. **開新的機會情報卡**，規則：
   - 標題跟同一主題線上所有既有卡片不同，具體點出這次新進展是什麼
   - `topicId`沿用同一條主題線的既有值，讓血緣可追溯
   - 正文結構、AI視角區塊、往知識庫閱讀雙狀態接點，完全比照既有規範，不因為是迭代卡就放寬標準
   - `signal`欄位具體寫出「這是第幾次獨立來源驗證同一條主題線」
4. **不修改任何舊卡片**，新舊卡片透過`relatedOpportunities`互相參照
5. 若新進展份量重大、可能推翻或補強既有知識庫/藍圖結論，同步標記進入Part B驗證

## Part B：創業藍圖「小白＋AI協作」視角驗證 SOP（通用）

### B1. 核心原則：用真實的「技術小白＋LLM協作」人格測試，不是用AI自己的理解力測試

**這個人格設定不是虛構的假設，是當今所有有熱情投入AI協作、但不具備寫程式能力者的實際樣貌，往後遇到任何新項目都照這個標準驗證：**

> 我不會寫程式碼，不會自己看懂錯誤訊息、不會自己排查bug。但我願意也懂得用自然語言跟Claude、Gemini這類LLM AI對話協作——我會把畫面截圖貼給AI看、把錯誤訊息複製貼給AI、照AI教我的步驟一步步做，讓AI當我的技術翻譯跟操作嚮導。

**判斷標準不是「這個技術描述AI看不看得懂」，是「小白會不會知道下一步該把什麼東西丟給AI」。**

### B2. 具體技術驗證項目（每次替換成當次主題的實際待驗證問題）

這一節每次執行時要替換成當次主題真正該驗證的技術問題。**本次示範案例：OpenMontage的HyperFrames角色一致性**——先前判定短劇需要的跨集角色一致性沒有解決，這次查證發現HyperFrames支援SVG角色綁定＋姿勢庫＋GSAP動作時間軸可能是解法，必須實測驗證：

1. 用零金鑰模式，透過Claude Code指定使用HyperFrames渲染引擎，走character-animation相關pipeline
2. 建立一個簡單角色，用SVG角色綁定方式定義
3. 讓同一角色在至少兩個不同場景/段落出現，渲染後人工目視比對外觀是否一致
4. 記錄過程中的設定步驟、小白會卡在哪一步、一致性真實表現（一致/部分一致/不一致）
5. 誠實記錄結果，驗證失敗本身就是重要情報，回頭按Part A流程開新卡片記錄

### B3. 小白＋AI協作驗證的具體檢查項目

- [ ] 教程裡有沒有任何一句指令，小白讀完不知道下一步該做什麼
- [ ] 教程有沒有假設讀者已經懂某個技術詞彙，卻沒有解釋
- [ ] **教程有沒有明確引導小白「卡關時該怎麼把問題丟給AI」**（例如：截圖貼給AI、複製錯誤訊息貼給AI），而不是假設小白會自己查文件排錯
- [ ] **教程裡的每一個技術步驟，是不是都能轉成「一句話請AI幫忙做」的形式**，而不是要求小白自己動手打複雜指令
- [ ] 照著教程的步驟，小白（搭配AI協作）能不能真的做出第一支demo（不要求完美，要求做得出來）
- [ ] 卡關的地方，教程有沒有給出「怎麼辦」的指引
- [ ] 讀完教程，小白知不知道下一步該去哪裡（下一步CTA是否清楚）

### B4. 驗證後的產出

通過：記錄「已通過小白＋AI協作驗證，日期XXX」。
沒通過：具體列出卡住的段落跟原因，回頭比照創業藍圖操作手冊規則修正，修正後必須重新走一次驗證。
