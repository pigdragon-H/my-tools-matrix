# PURPOSE

This document defines the single universal architecture for every tool in Formula Universe. It merges the product philosophy, the 17-layer business-and-knowledge architecture, and the golden corrected visual/code template that every generated tool must follow.

Formula Universe does not build isolated calculators. Formula Universe builds decision systems. Every tool must become a knowledge assistant, decision assistant, business asset, semantic network node, and AI-native product surface.

---

# CHAPTER 1 — CORE PHILOSOPHY

Formula Universe is not a traditional calculator website.

A traditional tool website usually follows this shallow path:

Input → Calculate → Result → Leave

Formula Universe must follow this deeper path:

Input → Calculation → Interpretation → Decision → Journey → Knowledge → Business → Premium → Long-Term Relationship

Every tool must answer five mandatory user questions:

1. What does the result mean?
2. Why should the user care?
3. What should the user do next?
4. What tool should be used next?
5. What knowledge should be learned next?

AI agents must understand that the calculator result is only the entry point. The real product is the interpretation, decision guidance, semantic journey, authority knowledge, commercial readiness, and trust system surrounding that result.

---

# CHAPTER 2 — GOLD TOOL FACTORY STRUCTURE

Each tool contains 17 layers.

These layers are business and knowledge functions. They must also be reflected in the page structure so users can visually experience the decision journey in a consistent order.

The golden visual layout after template generation must follow this visible page pattern:

- Layers 1–3: Hero area, usually a 2-column layout.
- Layers 4–5: Calculator area, usually a 2-column layout.
- Layers 6–7: Result card and result guidance area, usually a 2-column layout.
- Layer 8: Commercial Layer A / AdSlot reserve.
- Layers 9–10: Emotion + Conversion area, usually two 2-column layouts.
- Layer 11: Decision Path or Semantic Journey, usually a 4-step flow.
- Layers 12–13: Knowledge + FAQ, usually side-by-side 2-column layout.
- Layer 14: Commercial Layer B / AdSlot reserve after knowledge consumption.
- Layers 15–16: Recommendation + Premium Gate.
- Layer 17: Trust / references / research.

The visual layout exists to make the invisible business architecture understandable to users. AI agents must not treat the visual layout as decoration. It is the visible expression of the product strategy.

---

# CHAPTER 3 — THE 17 LAYERS

## Layer 1 — Hero Header

Purpose: Trust, identity, recognition.

User question answered: “Am I in the right place?”

Required content: tool name, short description, target audience, example use case, language switch, primary CTA.

Visual role: appears at the top of the Hero area, usually as the left side of a 2-column hero layout. The right side may show a quick action card, sample result, or example scenario.

Why AI must do this: users decide within seconds whether the page matches their intent. The Hero Header prevents abandonment by confirming topic, use case, and credibility immediately.

Failure examples: generic titles, missing audience, no example, no CTA, or a hero that does not clearly identify the tool.

---

## Layer 2 — Hero Context

Purpose: usage scenario and user fit.

User question answered: “When should I use this tool, and is it meant for my situation?”

Required content: when to use, who should use, common situations, and practical context.

Visual role: appears near the Hero area, often as supporting text, trust note, scenario cards, or context blocks under/near Layer 1.

Why AI must do this: tools without context become generic input forms. Context turns the tool into a relevant assistant for a specific user situation.

Failure examples: vague intro text, no mention of scenarios, or copy that could apply to any calculator.

---

## Layer 3 — Quick Start Guide

Purpose: reduce friction.

User question answered: “How do I start quickly?”

Required content: Step 1, Step 2, Step 3. The steps must be specific to the tool.

Visual role: part of the Hero or early guidance area, often next to an example card or above the calculator input.

Why AI must do this: users should not need to understand the whole domain before using the tool. Quick Start gives them a low-friction path into action.

Failure examples: generic steps like “enter values, click calculate, read result” without tool-specific guidance.

---

## Layer 4 — Calculator Input

Purpose: collect context, not just numbers.

User question answered: “What information do I need to provide?”

Required content: all required input fields, labels, helper text, units, defaults, validation hints, and context fields where useful.

Visual role: first half of the calculator area, usually a form/card in a 2-column layout.

Why AI must do this: high-quality tools collect enough context to produce meaningful interpretation, not just raw arithmetic.

Examples: BMI may ask height, weight, age, and gender; mortgage may ask home price, down payment, interest rate, term, and income context.

Failure examples: unlabeled inputs, missing units, no validation, or only collecting numbers when interpretation requires context.

---

## Layer 5 — Calculation Engine

Purpose: formula processing.

User question answered: “Is the calculation correct and safe?”

Required content/code: validated inputs, calculation logic, error handling, edge-case handling, domain-specific formula, and clear separation between formula logic and UI.

Visual role: often invisible, but its output powers the result cards. It belongs to the calculator area functionally even if not displayed as a separate UI block.

Why AI must do this: Formula Universe depends on factual and computational trust. Incorrect formulas destroy the product.

Content/code requirement: AI must research and verify formulas when uncertain. AI must not invent formulas, medical claims, financial assumptions, or references.

Failure examples: unvalidated division by zero, invented formula, missing edge cases, formula text not matching calculation logic, or replacing formula with unrelated copy.

---

## Layer 6 — Result Intelligence

Purpose: transform numbers into meaning.

User question answered: “What does my result mean?”

Required content: result, interpretation, risk level or category, recommendation, and key secondary metrics.

Visual role: first half of the result card area, usually a prominent result card plus metric cards in a 2-column result section.

Forbidden pattern: “BMI = 22. Done.” Raw results are not enough.

Why AI must do this: users need interpretation, not only output. Result Intelligence turns calculation into understanding.

Failure examples: raw number only, no category, no explanation, no warning, no recommendation.

---

## Layer 7 — Decision Advisor

Purpose: convert information into action.

User question answered: “What should I do next?”

Required content: next action, what to monitor, mistakes to avoid, and decision guidance based on result level.

Visual role: second half of the result card area, usually adjacent to Layer 6 as guidance, insight cards, scenario comparison, or advisor cards.

Why AI must do this: Formula Universe is decision infrastructure. The result must lead to action or judgment.

Failure examples: general advice unrelated to the calculated result, no next step, no mistake warning, or advice that crosses into unqualified medical/financial directives.

---

## Layer 8 — Commercial Layer A / AdSlot Reserve

Purpose: future monetization reserve before deeper engagement.

User question answered: none directly; this is a business infrastructure layer.

Required content/code: an ad reserve placeholder or disabled commercial slot controlled by feature flags.

Visual role: appears after the early calculator/result section and before deeper emotional/conversion sections.

Why AI must do this: every tool must be business-ready even when monetization is disabled. The reserve prevents future layout disruption.

Current status: placeholder only unless ads are explicitly enabled.

Possible future use: Google AdSense, sponsors, partnerships.

Failure examples: hardcoded active ads without flags, unlabeled ad UI, ad inserted inside forbidden knowledge/formula content, or missing reserve.

---

## Layer 9 — Emotion Layer

Purpose: human connection.

User question answered: “How should I feel about this result, and how do I stay confident?”

Required content: encouragement, motivation, reassurance, or caution written responsibly for the tool domain.

Visual role: first part of the Emotion + Conversion area, usually one of two 2-column layouts.

Why AI must do this: decisions are emotional as well as rational. This layer helps users stay engaged without fear, confusion, or shame.

Example: “You are currently in a healthy range. Maintaining current habits is recommended.”

Failure examples: fear-mongering, shame language, exaggerated promises, or generic motivational filler.

---

## Layer 10 — Conversion Layer

Purpose: move users forward.

User question answered: “Where should I go next?”

Required content: next recommended tools, next recommended learning, save/share actions, or journey continuation CTAs.

Visual role: second part of the Emotion + Conversion area, often paired with Layer 9 in two 2-column layouts.

Why AI must do this: Formula Universe must increase journey depth. Users should not stop at one result if related decisions remain.

Example BMI next tools: BMR, Calories, Body Fat, Weight Loss.

Failure examples: no next tool, unrelated CTA, generic CTA, or recommendations not based on semantic relationship.

---

## Layer 11 — Semantic Journey Engine

Purpose: build tool relationships.

This is one of the most important layers.

User question answered: “What is the logical decision path after this tool?”

Required content: semantic next tools, upstream/downstream relationship, journey path, and tool relationship explanation.

Visual role: often appears as a 4-step Decision Path flow or semantic journey path. It may also support internal links and recommendation systems.

Why AI must do this: without this layer, tools become isolated islands. Semantic relationships power SEO, internal linking, journey systems, recommendations, AI advisors, premium products, and affiliate products.

Example BMI journey: BMI → BMR → Calories → Protein → Body Fat → Progress.

Example CAGR journey: CAGR → Investment → Retirement → Withdrawal → Estate Planning.

Failure examples: missing related tools, random related tools, no journey logic, no semantic mapping, or using semantic copy to replace the L12 formula.

Important distinction: semantic relationships are mandatory, but they do not replace Layer 12 Knowledge content. L11 builds relationships; L12 teaches authoritative knowledge.

---

## Layer 12 — Knowledge Layer

Purpose: become an authority source.

User question answered: “What should I understand about this topic?”

Required content: definition, formula, interpretation, context, limitations, and examples.

Visual role: appears after the decision/journey section and before/alongside FAQ. In the golden layout, Layers 12–13 are usually presented as a 2-column Knowledge + FAQ section.

Why AI must do this: the Knowledge Layer builds Google ranking, AI search ranking, topical authority, and user trust. It also prevents users from misusing the result.

Formula requirement: every tool with a calculation must expose the relevant formula or method in this layer. BMI may show metric and imperial formulas in a special formula block; finance tools must show their financial formulas; developer tools must show parsing/validation rules or algorithmic logic where applicable.

Required quality: all definitions, formulas, limitations, and examples must be factual. If uncertain, research first and write later.

Failure examples: missing formula, semantic-neighbor text replacing formula, generic content, no limitations, no examples, no context, or unreferenced authoritative claims.

---

## Layer 13 — FAQ Layer

Purpose: capture long-tail search traffic and answer real user questions.

User question answered: “What else do people commonly need to know?”

Required content: real questions, not filler content. Questions must match the tool topic and user intent.

Visual role: appears side-by-side with Knowledge in the golden 2-column Knowledge + FAQ layout.

Why AI must do this: FAQ expands search coverage, handles objections, clarifies limitations, and improves user confidence.

Example BMI questions: Is BMI accurate? Is BMI useful for athletes? Can BMI measure body fat? What are BMI limitations?

Failure examples: placeholder FAQ, repeated questions, generic SEO filler, or advice beyond the tool’s authority.

---

## Layer 14 — Commercial Layer B / AdSlot Reserve

Purpose: high-intent monetization after knowledge consumption.

User question answered: none directly; this is business infrastructure placed after value delivery.

Required content/code: ad reserve placeholder or disabled commercial slot controlled by feature flags.

Visual role: appears after Knowledge + FAQ, not inside Knowledge, and not between formula cards.

Why AI must do this: after users consume knowledge, they are more qualified and intent-rich. This is the correct place for future monetization without damaging trust.

Failure examples: ad inside L12 Knowledge, ad between formula and limitations, missing label, hardcoded active ad, or missing Layer 14 reserve.

---

## Layer 15 — Recommendation Layer

Purpose: affiliate revenue, partnership revenue, and user assistance.

User question answered: “What product, service, or resource could help me next?”

Required content: only semantic recommendations. Recommendations must match the tool result, topic, and user journey.

Visual role: appears after Layer 14, often paired near Premium Gate.

Why AI must do this: recommendations create business value only when they help the user. Random affiliate content damages trust and semantic architecture.

Example BMI recommendations: protein powder, body fat scale, fitness course.

Example Retirement recommendations: ETF, brokerage, investment course.

Failure examples: unrelated products, invented affiliate claims, medical/financial product recommendations without caution, or recommendations not tied to semantic journey.

---

## Layer 16 — Premium Layer

Purpose: advanced decision support, not generic membership sales.

User question answered: “What advanced help can I unlock if I need deeper support?”

Required content: premium plan concept, advanced features, decision support benefits, and disabled/flagged state if premium is not active.

Visual role: near Recommendation Layer, usually as a Premium Gate card or CTA block.

Why AI must do this: premium should extend the decision system, not interrupt it. It must be a natural continuation of the user’s journey.

Example BMI free vs premium: free BMI result; premium 8-week weight loss plan, weekly tracking, AI coaching, progress dashboard.

Failure examples: generic “upgrade now” copy, unrelated premium pitch, active payment claims without Stripe activation, or premium unrelated to the tool’s decision path.

---

## Layer 17 — Trust Layer

Purpose: explain why users should trust the information.

User question answered: “Why should I believe this tool?”

Required content: references, research, government sources, academic sources, methodology notes, and trust/disclaimer text where appropriate.

Visual role: final section of the page, often including trust statement, related references, and source list.

Why AI must do this: Formula Universe must be factual and authority-driven. Trust Layer protects the product from unsupported claims and improves credibility with users and AI search systems.

Examples: WHO, CDC, NIH, government publications, peer-reviewed research, CFPB, SEC, central bank publications, official standards, or domain-specific documentation.

Failure examples: invented references, vague “based on research” claims, no sources, internal notes leaked to users, or references unrelated to the tool.

# CHAPTER 4 — SEMANTIC NETWORK SYSTEM

The semantic network system is the hidden architecture of Formula Universe.

Most websites build pages. Formula Universe builds knowledge networks.

Semantic networks determine SEO, recommendations, AI advisor behavior, journey design, affiliate mapping, premium products, and internal linking.

No tool may exist without semantic relationships.

Every tool must define where the user came from, where the user should go next, what adjacent knowledge matters, and which recommendations are semantically valid.

Semantic examples:

BMI → BMR → Calories → Protein → Body Fat → Weight Loss

CAGR → Investment → Retirement → Withdrawal → Estate Planning

JSON → API → JWT → Regex → Deployment

AI agents must not confuse semantic networking with the L12 formula card. Semantic relationships belong primarily to Layer 11 and are also reflected in Layer 10, Layer 15, and related/trust areas. L12 must still contain Knowledge content, including Formula.

Business layers:

# CHAPTER 6 — CONTENT AND CODE GENERATION RULES

Every tool must contain tool-specific content code. AI must research and verify before writing. AI must not invent professional formulas, medical advice, financial advice, references, or product claims.

The generated tool must include these content/code categories:

1. Type definitions: tool-specific professional category, result category, FAQ item structure, semantic relationship structure, recommendation structure, and state types where applicable.
2. Data definitions: category information, localized text, FAQ, references, examples, semantic journey, recommendations, premium copy, and trust copy.
3. Calculation logic: domain-specific professional formula, validated input conversion, edge cases, result category mapping, and error handling.
4. State management: input state, result state, language state, unit state, scenario/example state, UI interaction state, and share/save state where needed.

AI-generated content must be factual, referenced, useful, actionable, and specific to the tool.

Forbidden content:

- Empty text.
- Generic content.
- Placeholder FAQ.
- Invented medical advice.
- Invented financial advice.
- Invented references.
- Semantic recommendations that are not actually semantic.
- Formula text replaced by unrelated journey or related-tool copy.

If uncertain: research first, write later.

# CHAPTER 7 — GOLDEN VISUAL TEMPLATE

The golden corrected page structure should be visually inspectable in this order:

1. Layers 1–3: Hero area in a 2-column layout. One side explains identity/context; the other side provides quick start, example, or CTA.
2. Layers 4–5: Calculator area in a 2-column layout. One side may hold examples or guidance; the other side holds inputs and calculation controls.
3. Layers 6–7: Result card area in a 2-column layout. One side shows primary result intelligence; the other side shows advisor/scenario/decision interpretation.
4. Layer 8: AdSlot reserve.
5. Layers 9–10: Emotion + Conversion area, usually two 2-column layouts to connect emotionally and move the user forward.
6. Layer 11: Decision Path / Semantic Journey, usually a 4-step flow.
7. Layers 12–13: Knowledge + FAQ in a 2-column side-by-side layout.
8. Layer 14: AdSlot reserve after knowledge consumption.
9. Layers 15–16: Recommendation products/resources + Premium Gate.
10. Layer 17: Trust, references, and research.

AI agents may adapt details for responsive design, but the order and functional meaning must remain intact.

# CHAPTER 8 — QUALITY GATE

A tool fails if any required layer is missing.

Required functions:

- Hero.
- Calculator.
- Result.
- Advisor.
- Journey.
- Knowledge.
- FAQ.
- References.
- Commercial Reserve.
- Premium Reserve.
- Trust.
- Semantic Mapping.

A tool passes only when complete.

Minimum QC checks:

1. All 17 layers exist and are identifiable.
2. Layer order follows the golden visual template.
3. Calculation formula exists, is correct, and matches calculation logic.
4. L12 Knowledge includes Definition, Formula, Interpretation, Context, Limitations, and Examples.
5. L11 Semantic Journey exists and links the tool into a meaningful network.
6. FAQ uses real topic-specific questions, not filler.
7. Commercial slots are reserved, labeled, and controlled by flags.
8. Recommendations are semantic, not random affiliate content.
9. Premium layer offers advanced decision support, not generic membership copy.
10. Trust layer includes real references or clearly documented source requirements.
11. No invented professional advice, false claims, or fake references.
12. No ad is placed inside Knowledge formula content.
