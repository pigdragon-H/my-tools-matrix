# 單人短影音生產線基礎方案：以OpenMontage為核心的可執行架構

如果你是剛起步的創作者、自由工作者、或正在尋找低成本內容變現切入點的創客，這份方案會告訴你：只靠一台電腦、一個程式代理訂閱、以及一套開源系統，能不能真正做出可發布的短影音，以及做不到的部分該怎麼補。這不是一份「裝上就賺錢」的話術，是企業實際操作一遍後，把可行與不可行都寫清楚的基礎架構。

## 這是什麼生意

把短影音製作重新定義成「維護一條軟體生產線」，而不是每支影片都從零開始的剪輯專案。核心工具是開源的OpenMontage，搭配Claude Code或Codex等程式代理下達白話指令，代理自動完成研究、腳本、素材、剪輯、渲染。生意本身有兩層：第一層是你自己用這條生產線量產內容變現；第二層是把「怎麼搭這條生產線」變成教學/顧問服務，賣給還不會用的人。

## 為什麼現在值得做

同一組「AI代理＋開源工具鏈」的方法論，正在被多個獨立來源反覆驗證，顯示這不是曇花一現的話題，是正在成熟的技術路線。企業實測證實了兩件重要的事：一是環境安裝門檻比想像中低（約四分鐘可完成），二是代理具備真實的自我修復能力，能在遇到權限不足、路徑錯誤、編碼衝突時自行排除，不需要使用者具備程式背景介入。這代表切入時機在於「技術路線已被驗證可行，但市場上懂得完整操作的人還不多」，資訊落差本身就是機會。

## 目標客群

沒有剪輯背景、但需要穩定產出教學/解說/知識型短影音的個人創作者；需要低成本內容矩陣的小型行銷團隊；想學會這套流程再轉賣顧問服務的自由工作者。

## 收入模型

第一種是直接內容變現，靠自己的頻道流量與廣告分潤；第二種是顧問/教學服務，收費教別人怎麼搭建這條生產線；第三種是企業代操，替沒有時間學習的中小企業客戶代為產出內容。三種模型可以並行，初期建議先跑通第一種驗證流程本身，再逐步發展第二、三種。

## 成本結構

| 項目 | 一次性成本 | 持續成本 |
|---|---|---|
| 程式代理訂閱（如Claude Pro） | 無 | 約每月20美元起 |
| OpenMontage環境安裝 | 約4分鐘、825MB磁碟空間 | 無 |
| 零金鑰模式素材（本地語音、免費音樂） | 無 | 無，但品質有限 |
| 付費語音服務（若語音品質不達標） | 無 | 依用量計費，需另評估 |
| 人力時間（腳本審核、視覺複檢） | 無 | 每支影片約需人工介入處理決策節點 |

## 工具與工作流

整體架構分三層，任何一層缺失都無法完整運作：

```
┌─────────────────────────────────────┐
│  第一層：驅動  程式代理               │
│  Claude Code／Codex／其他相容工具     │
└──────────────────┬────────────────────┘
                   │ 讀取白話指令，執行檔案操作
┌──────────────────▼────────────────────┐
│  第二層：車體  OpenMontage             │
│  流程編排／規則檔案／品質檢查           │
└──────────────────┬────────────────────┘
                   │ 調度底層工具
┌──────────────────▼────────────────────┐
│  第三層：引擎  底層工具組                │
│  渲染引擎／語音引擎／素材來源             │
└─────────────────────────────────────┘
```

第一層是駕駛，負責理解需求並執行操作，市面上常見選擇是Claude Code或Codex命令列工具，需要獨立訂閱。第二層是車體，負責把創作流程拆解成固定步驟並把關品質，這層免費開源。第三層是引擎，實際產生畫面與聲音，零成本模式下靠本地渲染與本地語音引擎運作，若要提升品質，這層是最需要額外投資的地方。

### 🚨 關鍵限制與繞行方案（Kling 與 GPU 本地推理）

企業實測發現，OpenMontage 的零金鑰模式在**角色一致性**上存在致命缺陷：其 SVG 渲染模組（CharacterRigRenderer）無法讀取角色外觀描述，只會輸出硬編碼的幾何圖形。

**繞行方案 1：外部付費 API（如 Kling / Seedance）**
最直接的解法是「排版用 OpenMontage，渲染交給外部工具」。你可以讓 OpenMontage 輸出 `edit_decisions.json`，然後把每個場景交給外部模型渲染。
* **注意**：我們查證了 OpenMontage 的程式碼，發現其內建的 Kling 工具（`kling_video.py`）**尚未實作** Kling 3.0 的多角色參考參數（`reference-to-video`）。因此，你不能直接用內建的 Kling 工具解決角色一致性問題。
* **解法**：改用 OpenMontage 內建的 Seedance 2.0 工具（已完整實作多圖片參考參數），或自行撰寫 100-200 行的 Python 腳本，直接呼叫 FAL.ai 的 Kling API。

**繞行方案 2：GPU 本地推理**
如果你有強大的本地 GPU 資源，可以將 OpenMontage 的底層渲染引擎替換為本地的 ComfyUI 工作流。透過客製化的 ComfyUI 節點（如 IP-Adapter 結合 AnimateDiff），在本地實現角色一致性渲染，完全免除 API 呼叫成本。

## 30/60/90天執行計畫

第一個30天，目標是跑通技術流程：安裝環境、產出第一支demo影片、記錄每一個卡關點與解法，這個階段不追求內容深度，追求「流程能不能跑通」。第二個30天，目標是轉為主導式協作：不再放手讓代理自主研究選題，改由自己先寫好腳本與視覺規範，代理只負責執行，驗證這條路徑能不能穩定輸出可發布內容。第三個30天，目標是建立節奏與差異化：固定發布頻率，開始累積作品集，評估要不要往顧問/教學服務發展第二收入模型。

## 主要風險

技術執行順暢不代表創意判斷也能自動化——企業實測中，代理需要人工確認的節點超過二十次，非技術背景使用者可能在決策密度上感到負擔；零成本語音品質不足，若誤判自己的內容形式離不開旁白，會在後期才發現卡關；視覺細節（例如顏色參數是否正確傳遞）需要具備基礎程式閱讀能力才能排查，完全不懂技術的人這一步可能需要另外找人協助。

還有一項容易被低估的風險，是決策疲勞造成的中途放棄。企業實測全程記錄下來，光是環境安裝到第一支demo完成，就經歷了二十幾次「是否放行」的確認畫面，對熟悉技術的人來說這些畫面多半一眼就能判斷安全與否，但對完全不具備任何技術背景的人，每一次都可能是一次重新評估、重新猶豫的關卡。如果沒有事先做好心理準備，很容易在流程還沒走完的中途就選擇放棄，錯過真正看到成果的那一刻。這也是為什麼企業建議第一輪先撥出完整時間、不追求內容完美，把重點放在「撐過這整段流程」本身。

## 不適合誰

如果你完全無法接受任何形式的技術設定（哪怕只是照著步驟裝軟體），這條路徑不適合你；如果你的內容形式高度仰賴真人出鏡或現場感實拍素材，這套零成本工具鏈幫不上忙；如果你追求的是「完全不用管、AI自動生出完美成品」，目前的技術成熟度還沒到那裡，需要你持續參與主題判斷與品質把關。

同樣不適合的，是期待「一次性投入、之後完全不用維護」的人。這條生產線的價值在於長期使用後的複利效果——第一次搭建的成本相對固定，但真正的效益要等到你用它產出第十支、第二十支影片時才會顯現。如果你只打算做一兩支影片測試水溫，投入學習環境安裝的時間成本可能不划算，直接找人代工或用現成的手機剪輯App反而更划算。

## 🚀 動手之前，先問自己這幾個問題

1. **你有沒有辦法先撥出一個完整的週末，只用來跑通環境安裝與第一支demo，不求內容完美？** 引導思路：這條路徑最大的隱形成本是學習曲線，先體驗過一次完整流程，才知道自己撐不撐得下去。
2. **你的內容形式，能不能接受初期沒有旁白、只有文字卡搭配音樂？** 引導思路：語音是目前最大的品質短板，先確認你的內容類型離不離得開真人水準的配音，決定你要不要先投入額外的語音成本。
3. **遇到看不懂的錯誤訊息時，你會選擇直接把訊息丟給AI代理處理，還是會因為看不懂就放棄？** 引導思路：企業實測顯示多數技術性障礙代理都能自行排除，真正的風險不是技術本身，是使用者心理上能不能撐過那個「看起來卡住了」的瞬間。

## 結語

這份基礎方案能讓你驗證「這條路走不走得通」，但真正要變成穩定的變現事業，還需要你依據自己的內容領域做客製，例如固定的分鏡結構、專屬的品牌視覺規範，以及後續的發布排程與數據復盤機制。這部分企業目前也仍在驗證中，下一輪會改由人工先備妥完整腳本與視覺規範，再交給程式代理執行，用以檢驗這條路徑能不能真正撐起商業化產出的品質門檻，屆時會有更新的實作記錄可供參考。
