# CSV 轉 JSON 工具使用指南：如何整理資料格式並避免欄位轉換錯誤

在系統開發與數據處理的日常中，我們經常遇到一種尷尬的情境：行銷或營運團隊提供了一份用 Excel 整理好的 `.csv` 檔案，裡面包含了幾千筆商品資料或會員名單，但後端 API 或前端網頁需要的是 `.json` 格式的資料才能進行渲染或儲存。如果手動用程式語言寫腳本來轉換，雖然不難，但往往需要處理引號跳脫、逗號分隔、換行字元等瑣碎問題。CSV 轉 JSON 工具就是為了解決這個繁瑣的資料對接過程而生，協助快速完成格式轉換，但仍需確認工具的資料處理方式與轉換結果。

## 工具是什麼

CSV 轉 JSON 工具是一款將逗號分隔值（Comma-Separated Values, CSV）的純文字資料，轉換為 JavaScript 物件表示法（JavaScript Object Notation, JSON）的線上處理工具。

它的核心運作原理是解析 CSV 的第一行作為 JSON 物件的鍵（Key / Property Name），並將後續的每一行資料對應轉換為該鍵的值（Value）。最終，整份 CSV 檔案會被轉換為一個包含多個 JSON 物件的陣列（Array of Objects），這種格式非常適合直接匯入資料庫（如 MongoDB）或作為 RESTful API 的回傳格式。

## 適合誰使用

這款工具適合需要頻繁處理跨系統資料格式的人員：

*   **前端開發者**：需要將客戶提供的靜態 CSV 資料，快速轉換為 JSON 以便在網頁上用迴圈（如 React 的 map）渲染成表格或列表。
*   **後端開發者**：需要將舊系統匯出的 CSV 資料，轉換為 JSON 格式以便批次寫入新的 NoSQL 資料庫。
*   **數據分析師**：在將資料餵給某些只接受 JSON 格式的資料視覺化工具（如 D3.js）前，進行格式前置處理。
*   **企劃與營運人員**：雖然不懂寫程式，但需要將手邊的 Excel 表格轉換為工程師指定的 JSON 格式以利上稿。

## 使用前需要準備什麼

為了降低轉換錯誤並便於後續檢查，請先檢查您的 CSV 檔案：

1.  **確認是否有標題行（Header Row）**：CSV 的第一行必須是欄位名稱（如 `id, name, price`），這將成為 JSON 的 Key。如果沒有標題行，轉換結果可能難以對應欄位意義。
2.  **檢查分隔符號**：雖然叫 CSV，但有些檔案可能是用分號（`;`）或定位符（`Tab`）分隔。確認您的檔案使用的是標準的逗號（`,`）。
3.  **處理特殊字元**：如果您的資料內容本身包含逗號或換行符號（例如商品描述），請先確認在匯出 CSV 時，這些欄位有被雙引號（`"`）正確包覆。

## 欄位與輸入資料說明

進入 CSV 轉 JSON 工具後，您通常會看到以下操作區塊與選項：

*   **輸入區（Input CSV）**：您可以直接將 CSV 文字貼上，或者選擇上傳 `.csv` 檔案。
*   **分隔符號設定（Delimiter）**：預設為逗號（`,`），但您可以根據檔案實際情況更改為分號或 Tab。
*   **自動型別判斷（Parse Numbers/Booleans）**：這是一個重要的進階選項。勾選後，工具會嘗試將看起來像數字的 `123` 轉換為 JSON 的數字型別，而不是字串 `"123"`；將 `true` 轉換為布林值，而不是字串 `"true"`。
*   **輸出區（Output JSON）**：顯示轉換後的 JSON 結果，通常會提供複製或下載 `.json` 檔案的按鈕。

## 如何解讀結果

轉換完成後，您會得到一段結構化的 JSON 程式碼。

1.  **陣列結構**：最外層通常是一個方括號 `[` 和 `]`，代表這是一個陣列。
2.  **物件對應**：陣列裡面的每一個大括號 `{}`，對應到 CSV 檔案中的一行資料。
3.  **鍵值對（Key-Value Pairs）**：大括號內的屬性名稱（如 `"product_name"`）來自 CSV 的第一行，屬性值（如 `"Apple"`）來自對應的資料行。
4.  **格式化顯示**：優良的工具會自動進行 Pretty Print（縮排與換行），讓 JSON 結構易於人類閱讀與檢查。

## 常見錯誤與注意事項

在進行 CSV 到 JSON 的轉換時，請特別留意以下常見問題：

*   **數字變成字串**：如果您的後端資料庫要求 `price` 必須是數字（Number），但轉換後變成了字串（String `"100"`），可能會導致後續計算錯誤。請確認是否開啟了自動型別判斷，或在轉換後進行二次處理。
*   **前導零消失**：對於電話號碼（如 `0912345678`）或身分證字號，如果開啟了自動轉數字，前導零可能會被消除變成 `912345678`。這類資料應該強制保留為字串型別。
*   **標題行包含空格或特殊字元**：如果 CSV 的標題是 `Product Name`（中間有空格），轉換後的 JSON Key 也會是 `"Product Name"`。在 JavaScript 中，這種 Key 無法用點記法（`obj.Product Name`）存取，只能用括號記法（`obj["Product Name"]`）。建議在轉換前，先將 CSV 標題改為駝峰式（`productName`）或底線式（`product_name`）。
*   **檔案編碼問題**：如果您的 CSV 包含中文字，請先確認檔案是以 UTF-8 編碼儲存，否則轉換後的 JSON 可能會出現亂碼。

## FAQ

**Q1：轉換後的 JSON 檔案可以直接匯入資料庫嗎？**
A1：通常可以。大多數現代資料庫（如 MongoDB, PostgreSQL）和後端框架都原生支援匯入或解析 JSON 陣列。但請先確認您的資料庫是否對 JSON 的層級結構有特定要求。

**Q2：如果我的 CSV 檔案非常大（例如超過 50MB），線上工具跑得動嗎？**
A2：這取決於您的瀏覽器效能與工具的設計。對於超大型 CSV 檔案，瀏覽器可能會因為記憶體不足而當機。建議將大檔案分割成多個小檔案再轉換，或者使用命令列工具（如 Node.js 腳本）在本地端進行處理。

**Q3：為什麼轉換後，有些欄位的值變成了 `null` 或空字串 `""`？**
A3：這表示在原始的 CSV 檔案中，該行對應的欄位是空白的（例如兩個逗號連在一起 `,,`）。這是正常的轉換結果，您的程式碼在處理 JSON 時應該要能適當處理這些空值。

**Q4：我可以將 JSON 再轉回 CSV 嗎？**
A4：可以，但需要注意的是，JSON 可以表達多層狀的巢狀結構（Nested Objects），而 CSV 只能表達扁平的二維表格。如果 JSON 包含巢狀結構，轉回 CSV 時可能需要進行扁平化處理（Flattening），這可能會導致資料結構改變。

**Q5：資料轉換的過程安全嗎？我的資料會被存到伺服器上嗎？**
A5：若工具採用純前端設計，通常可在瀏覽器本地端（Client-side）透過 JavaScript 進行轉換；但實際資料處理方式仍應以工具頁說明、瀏覽器環境與使用者自身資安要求為準。但如果您處理的是極度機密的客戶個資，建議在斷網狀態下使用，或自行撰寫本地腳本轉換，降低資料外流風險。

**建議注意以下限制：**
1.  **型別判斷不一定符合業務邏輯**：自動型別判斷可能無法完全符合您的業務邏輯需求（例如前導零遺失問題），建議在匯入正式系統前人工抽查轉換結果。
2.  **不處理業務邏輯**：本工具僅進行語法格式的轉換，不會檢查您的資料內容是否合理或合法。
3.  **效能限制**：本工具適用於一般日常大小的檔案轉換，不建議用於處理 GB 級別的巨量資料庫備份檔。
