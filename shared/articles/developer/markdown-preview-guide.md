# Markdown 預覽器指南：整理標題、清單、表格與程式碼區塊的編輯工具

## 文章摘要
寫 Markdown 時，最容易忽略的不是內容本身，而是標題層級、表格排版、程式碼區塊與連結在實際顯示時是否仍然清楚。Markdown 預覽器可協助你在發布前先看見排版結果，降低把原文貼進 CMS 之後才發現格式錯位的機率。

## 工具是什麼
Markdown 預覽器是一種用來即時顯示 CommonMark Markdown 排版結果的工具，支援標題、清單、連結、程式碼區塊與表格。它較適合用於文件撰寫、技術文章整理，以及發布前的格式檢查。

## 適合誰使用
技術寫作者、工程師、內容維護者、學生，以及需要編寫說明文件的人。

## 常見使用情境
1. 撰寫 README
2. 整理知識庫文章
3. 編寫 API 文件
4. 製作教學筆記
5. 檢查版本發布說明

## 使用前需要準備哪些資料
原始 Markdown 內容、目標平台支援範圍、是否需要表格或程式碼區塊，以及最終發布環境。

## 輸入欄位如何理解
- **Markdown 原文**：是主要輸入，應盡量接近最終發布版本。
- **標題層級**：可檢查文件結構是否清楚，不宜跳層過多。
- **連結與圖片語法**：需要確認語法與路徑是否正確。
- **程式碼區塊與表格**：這是最常在不同平台出現差異的區塊，預覽特別重要。

## 結果如何解讀
預覽結果可幫你檢查排版、結構與語法是否大致合理，但最終顯示仍可能受到實際 CMS、版本平台或樣式系統影響。若文章要上正式網站，仍建議在最終環境再做一次檢查。

## 實際案例
例如技術寫作者正在整理一篇部署教學，文件中包含多層標題、參數表格與 shell 指令區塊。她在 Markdown 預覽器中先檢查表格是否對齊、程式碼區塊是否關閉完整、內部連結是否可讀，再貼進 CMS。這能降低上線後才發現排版錯位或層級混亂的機率。

## 常見錯誤與注意事項
1. 標題跳層，讓文件結構難以閱讀。
2. 表格與程式碼區塊沒有完整關閉。
3. 只在編輯器內看原文，沒有預覽實際排版。
4. 以為所有平台都完全支援相同 Markdown 語法。

## FAQ
### Markdown 預覽器能代表正式網站顯示結果嗎？
可作為很實用的前置檢查，但不能完全取代正式網站或 CMS 的最終顯示。不同平台對 CommonMark、表格、任務清單與內嵌內容的支援程度可能不同，正式上線前仍建議再檢查一次。

### 為什麼我在某個平台可用的語法，這裡看起來不同？
因為不同平台可能加入擴充語法或自訂樣式。Markdown 預覽器通常偏向整理標準與常見語法，若你的平台有特殊擴充，還是要回到最終環境確認。

### 這個工具適合用來寫長文章嗎？
適合，尤其在你需要先整理結構、檢查標題層級與預覽排版時很有幫助。不過長文維護除了預覽外，也建議同步注意章節命名、內部連結與內容一致性。

### 表格看起來沒問題，就代表在手機上也好讀嗎？
不一定。Markdown 預覽器可先協助你檢查語法與基本排版，但不同網站在手機版的 CSS 處理可能不一樣。若文章會在行動裝置上大量閱讀，仍應在實際前端介面測試。

### Markdown 預覽器能不能取代版本比對？
不能。它擅長處理排版與內容可讀性，但若你要比較前後版本差異，仍需要搭配差異比對器或版本控制工具一起使用。
